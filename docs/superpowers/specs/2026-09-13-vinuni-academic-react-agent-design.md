# VinUni Academic ReAct Agent Design

**Goal:** Complete the Day 03 lab as a VinUni academic assistant that can look up a student record, book an academic-advising appointment, and record evidence of its ReAct decisions.

## Scope

The command-line application remains the entry point. It supports general policy questions, one-tool queries, appointment requests, a two-tool workflow, and unknown-student handling. No web server, persistent database, or third-party MCP transport is added; the existing in-process JSON-RPC simulation remains the MCP boundary.

## Components

- `src/tools.py` exposes two complete JSON schemas and contains the deterministic mock student data plus tool executors.
- `src/mcp_server.py` calls the tool router and wraps the decoded result in a JSON-RPC 2.0 response.
- `src/app.py` maintains a conversation context per request. Each tool result becomes an Observation message passed back to the provider, allowing a later decision to either call another tool or return a final answer.
- `src/providers.py` accepts that context for Mock, Gemini, and OpenAI providers. The Mock provider recognizes the supplied test cases deterministically, including a lookup-then-book flow.
- `config/test_cases.json` contains five executable VinUni academic-assistant cases.
- `docs/trace_eval.md` documents the selected topic and Agentic Fit score. The trace file is generated by the application and is not hand-authored.

## Data Flow

1. The user question and the available tool schemas are sent to the selected provider.
2. If the provider requests a tool, `app.py` calls `MCPAcademicServer.call_tool`.
3. The server invokes `dispatch_tool_call`, decodes its JSON string, and returns `{jsonrpc, server, tool, result}`.
4. `app.py` logs the action and observation, adds the observation to its request context, and asks the provider for the next action.
5. The agent stops on a text response or after `MAX_ITERATIONS`; a trace always records each completed action and final answer.

## Behavior Rules

- `schedule_appointment` requires `student_id`, `datetime_str`, and `advisor_name`.
- A lookup for an unknown student returns `NOT_FOUND`; the agent must report that result without fabricating details or booking an appointment.
- A two-tool request first runs `academic_query`, extracts the returned `advisor`, then calls `schedule_appointment` with that advisor.
- Live providers keep their native tool-calling APIs. Context is included as a concise serialized prior-observation block so they can continue the loop.
- The final response is built from the last provider text response when available; the Mock provider supplies deterministic final text for offline verification.

## Verification

Automated `unittest` coverage will verify the appointment JSON schema, JSON-RPC tool response, direct and unknown query handling, and the two-tool trace ordering. `python src/mcp_server.py` and `python src/app.py --all` will be run in Mock mode to validate the CLI workflow and trace generation.
